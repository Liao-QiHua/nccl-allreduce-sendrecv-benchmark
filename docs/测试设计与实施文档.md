# NCCL Reduce / SendRecv Benchmark 测试设计与实施文档

## 1. 两个核心目标

基于 NVIDIA/nccl v2.28.9-1，在同一台机器的两张 RTX PRO 5000 上，由两个 MPI 进程分别绑定一张 GPU，通过 PCIe P2P 测试 NCCL。

本项目只围绕两个结果：

1. **端到端延迟**：AllReduce 和双向配对 Send/Recv，分别测试 8 B、16 KiB、8 MiB，SIMPLE/LL 分开强制。
2. **8 B 阶段延迟**：统计 NCCL Host 函数和 GPU Kernel 完整执行时间，在 AllReduce / SendRecv 层级文本调用树的每个函数名后直接显示实测统计值，并展示父子、串行、并行和重叠关系。

## 2. 固定环境与参数

| 项目 | 配置 |
|---|---|
| NCCL | NVIDIA/nccl v2.28.9-1 |
| GPU | 2 × RTX PRO 5000 |
| 拓扑 | 同机 PCIe；运行前检查 P2P |
| MPI | 2 ranks；每进程一张 GPU |
| 数据类型 | FP32 |
| AllReduce | ncclSum |
| SendRecv | 每个 Rank 向对端发送，同时从对端接收 |
| Payload | 8 Byte、16 KiB、8 MiB |
| Protocol | SIMPLE、LL 分开强制 |
| Algorithm | 自动选择，记录实际选择 |
| Warmup / Measure | 20 / 100 |
| 阶段拆解 | 只测 8 Byte |

8 Byte 指两个 FP32 元素；16 KiB=16,384 Byte；8 MiB=8,388,608 Byte。

## 4. 协议与算法控制

分别设置：

    NCCL_PROTO=Simple
    NCCL_PROTO=LL

本测试只强制协议，不强制算法：不设置 NCCL_ALGO，让 NCCL 自动选择算法，并从 INFO 日志确认实际选择。协议不可用或实际选择不匹配时，将该配置标记为失败，不得静默回退。

## 5. 端到端测量定义（Baseline，无插桩）

使用官方未插桩 NCCL。每组测量：

1. MPI_Barrier 在计时区间外对齐两个 Rank。
2. Host monotonic timer 开始。
3. 调用 ncclAllReduce，或 ncclGroupStart + ncclSend/ncclRecv + ncclGroupEnd。
4. 调用对应 cudaStreamSynchronize，等待该轮通信完成。
5. Host monotonic timer 结束。
6. 在计时区间外汇总两个 Rank 的耗时，取 MAX 作为该轮整体通信完成延迟；保留两个 Rank 的原始耗时。

AllReduce 的计时范围为 API 提交前到对应 Stream 完成。SendRecv 的计时范围为一组双向 Send/Recv 提交前到对应 Stream 完成。Comm 初始化、连接建立和每轮 MPI Barrier 不计入单次 E2E。

记录每轮原始样本，计算 mean、P50、P90、P99、min、max。另行记录 Host API 函数驻留时间，但不得将 Host API 时间与 E2E 相加。

本测试为逐次同步的单操作延迟测试，不是批量异步吞吐测试。

## 6. 两套 NCCL 构建隔离

### Baseline

- NVIDIA/nccl v2.28.9-1 官方原始源码。
- 不应用 Host Trace Patch。
- 用于全部 E2E 测试。

### Trace

- 同一上游 Tag，独立源码目录。
- 应用 patches/nccl-v2.28.9-1-host-trace.patch。
- 编译启用 NCCL_ENABLE_HOST_TRACE=1。
- 运行启用 NCCL_HOST_TRACE=1 和 NCCL_HOST_TRACE_BYTES=8。
- 只用于 8 B 阶段拆解。

必须使用独立 build 输出和独立动态库搜索路径。用 ldd 确认测试程序加载正确的 libnccl.so。

## 7. Host 函数阶段计时

只在 Trace NCCL 上对 8 B 测试进行 Host 插桩。计时点包括：

- ncclSend
- ncclRecv
- ncclGroupStart
- ncclGroupEnd

### Task Append / Prepare / Plan

- ncclPrepareTasks
- ncclTasksRegAndEnqueue

### Launch

- doLaunches
- ncclLaunchPrepare

- ncclLaunchKernelAfter_NoCuda

### 条件连接预热

- ncclP2PPreconnectFunc：仅在实际执行时记录。若只在连接初始化或 Warmup 期间发生，不应混入正式 100 次统计；可单独报告初始化开销。

ncclGroupStartInternal 是 inline helper，当前不独立插桩；若没有独立事件，其开销包含在调用方的 Exclusive 区间中。

每条 Host 事件记录 event、rank、pid、tid、bytes、start_ns、end_ns、duration_ns。Group / group-wide 函数可能 rank=-1，使用 PID/TID 和时间线关联，不得虚构 Rank。

## 8. GPU Kernel 完整执行时间

**不修改 NCCL Device 源码，不在 Kernel 内部增加 clock64() 阶段插桩。**

只统计每个 NCCL GPU Kernel 的完整执行区间，使用测试侧 CUPTI Activity API 或 Nsight Systems 采集：

- Rank / GPU
- Kernel 名称
- CUDA Stream
- GPU Start / End
- Kernel Duration
- Grid / Block（工具可提供时）

一次通信可能发出一个或多个 Kernel，必须按实际采集结果逐个报告。多个 Kernel 存在重叠时，不得简单相加。

不同 GPU 的绝对设备时间戳未经时钟校准不能直接比较；可以分别计算每张 GPU 的 Kernel Duration，并使用 CUPTI/Nsight 的统一时间线分析重叠。

## 9. 父子函数、串行与并行分析

最终必须生成 AllReduce 和 Send/Recv 两棵带实测耗时的层级文本调用树。每个函数名后直接显示：

    [calls=N, mean inclusive=X us, mean exclusive=Y us, P50=..., P90=..., P99=..., min=..., max=...]

所有数值必须来自正式测量的 100 次，不包含 20 次 Warmup。函数每轮可能被调用多次，报告真实 calls 数量。

- Inclusive：函数完整区间。
- Exclusive：扣除直接子区间并集后的自身时间。
- 不得把父子 Inclusive 相加。
- 不得用父函数时间减去所有子函数 duration 的简单总和计算 Exclusive。
- 无法可靠推导的 Exclusive 标记 N/A，并解释原因。
- 未执行的条件分支标记 N/A，不得写 0 us。
- 异步线程回调要作为异步提交/执行关系展示，不能画成同步调用栈子函数。

同时生成 Rank 0 Host、Rank 1 Host、异步 Host Thread（如果存在）、GPU 0 Stream、GPU 1 Stream 的时间线，明确同线程串行、跨 Rank 并行、Host/GPU 重叠和 Kernel 等待关系。

GroupStart/GroupEnd 是 Group 逻辑作用域边界，不是 ncclSend/ncclRecv 的函数调用父节点。

## 10. Proxy 与传输路径

本轮不单独计时 Proxy Progress，不修改 Proxy 源码。目标是同机 PCIe Direct P2P，阶段测试设置 NCCL_P2P_USE_CUDA_MEMCPY=0。

仍必须从 NCCL INFO 日志确认实际 Transport。如果出现 NET/SHM、Proxy 或其他传输路径，如实报告；不允许把 Proxy 时间归入 Host API 或 GPU Kernel。

## 11. 正确性检查

AllReduce：Rank 0 输入 1.0，Rank 1 输入 2.0，所有输出应为 3.0。

SendRecv：Rank 0 输入 1.0，Rank 1 输入 2.0；Rank 0 接收结果应为 2.0，Rank 1 接收结果应为 1.0。

每种 operation/payload 检查全部 FP32 输出元素。任何正确性失败都必须停止该配置并保留日志。

## 12. 执行流程

1. 获取仓库最新代码，阅读测试文档和源码。
2. 检查 GPU、PCIe 拓扑、P2P、CUDA、Driver、MPI 和编译器。
3. 获取 NVIDIA/nccl v2.28.9-1，记录 commit SHA。
4. 检查 Patch 上下文，分别构建 Baseline 和 Trace。
5. 使用 Baseline 完成全部 E2E 测试。
6. 使用 Trace 仅完成 8 B Host 阶段测试。
7. 使用 CUPTI/Nsight 采集 GPU Kernel 完整执行时间。
8. 生成带时间的层级调用树、串并行时间线和性能分析报告。

需要修改测试代码或 NCCL 源码时，先说明原因、文件和对计时结果的影响，等待用户确认后再修改。

未经远端 GPU 主机实际应用、编译和运行验证的 Patch 不得标记为已验证。
