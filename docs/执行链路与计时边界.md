# NCCL v2.28.9-1 调用链、阶段计时与串并行关系

本文服务于两个测试目标：端到端延迟，以及 8 B AllReduce / SendRecv 的阶段延迟拆解。函数关系以 NVIDIA/nccl v2.28.9-1 源码为准；最终统计值必须由 Host Trace 和 GPU Activity 实测填充。

## 1. 计时输出的强制格式

最终报告中的每一个已插桩函数节点，必须在函数名后直接标注：

    functionName() [calls=N, mean inclusive=X us, mean exclusive=Y us, P50=..., P90=..., P99=..., min=..., max=...]

X/Y 只能来自实际数据。没有执行的条件路径标记 N/A，不得写 0 us。若 Exclusive 无法可靠推导，标记 N/A 并解释原因。

- Inclusive：函数完整区间。
- Exclusive：父函数区间扣除直接子区间并集后的自身时间。
- 不可将父子 Inclusive 直接求和。
- 对异步线程上的任务回调，按异步提交/执行关系展示，不要伪装成同步 C++ 子调用。

## 2. AllReduce 调用树

AllReduce 通过公开 API 隐式进入 NCCL Group。ncclEnqueueCheck 内部调用 Group Start Internal，执行 taskAppend，最后调用 ncclGroupEndInternal；当 Group 深度归零时，后者可能触发 groupLaunch。

~~~text
Rank N Host Thread
└── ncclAllReduce() [实测统计]
    └── ncclEnqueueCheck() [实测统计]
        ├── ncclGroupStartInternal() [inline helper；若无独立事件，计入父函数 Exclusive]
        ├── taskAppend() [实测统计]
        │   └── collTaskAppend() [实测统计]
        └── ncclGroupEndInternal() [实测统计]
            └── groupLaunch() [实测统计]
                ├── ncclP2PPreconnectFunc() [条件执行；未执行则 N/A]
                ├── ncclPrepareTasksAndCollPreconnect() [实测统计]
                │   ├── ncclPrepareTasks() [同步路径实测统计]
                │   └── ncclPrepareTasksAndCollPreconnectFunc() [异步路径；未执行则 N/A]
                ├── ncclTasksRegAndEnqueue() [实测统计]
                └── doLaunches() [实测统计]
                    ├── ncclLaunchPrepare() [实测统计]
                    │   └── scheduleCollTasksToPlan() [实测统计]
                    └── Launch Round Loop
                        ├── ncclLaunchKernelBefore_NoUncapturedCuda() [实测统计]
                        ├── ncclLaunchKernel() [实测统计]
                        ├── ncclLaunchKernelAfter_NoCuda() [实测统计]
                        └── ncclLaunchFinish() [实测统计]
~~~

说明：
- taskAppend / collTaskAppend 属于 AllReduce 的任务入队路径。
- scheduleCollTasksToPlan 属于 Collective Work 规划路径。
- scheduleP2pTasksToPlan 不应出现在普通 AllReduce 路径，除非实际代码路径确实调用。
- ncclPrepareTasksAndCollPreconnectFunc 只在对应异步配置路径执行。
- ncclP2PPreconnectFunc 仅在存在待连接 P2P Connector 时执行，常见于初始化/预热阶段。

## 3. Send/Recv 调用树

每个 Rank 在一个 Group 中依次提交 Send 和 Recv。GroupStart/GroupEnd 是逻辑作用域边界，不是 Send/Recv 的 C++ 函数调用父节点。

~~~text
Rank N Host Thread

ncclGroupStart() [实测统计；Group 逻辑作用域开始]

ncclSend() [实测统计]
└── ncclEnqueueCheck() [实测统计]
    ├── ncclGroupStartInternal() [inline helper；若无独立事件，计入父函数 Exclusive]
    └── taskAppend() [实测统计]
        └── p2pTaskAppend() [实测统计]

ncclRecv() [实测统计]
└── ncclEnqueueCheck() [实测统计]
    ├── ncclGroupStartInternal() [inline helper；若无独立事件，计入父函数 Exclusive]
    └── taskAppend() [实测统计]
        └── p2pTaskAppend() [实测统计]

ncclGroupEnd() [实测统计；Group 逻辑作用域结束]
└── ncclGroupEndInternal() [实测统计]
    └── groupLaunch() [实测统计]
        ├── ncclP2PPreconnectFunc() [条件执行；未执行则 N/A]
        ├── ncclPrepareTasksAndCollPreconnect() [实测统计]
        │   ├── ncclPrepareTasks() [同步路径实测统计]
        │   └── ncclPrepareTasksAndCollPreconnectFunc() [异步路径；未执行则 N/A]
        ├── ncclTasksRegAndEnqueue() [实测统计]
        └── doLaunches() [实测统计]
            ├── ncclLaunchPrepare() [实测统计]
            │   └── scheduleP2pTasksToPlan() [实测统计]
            └── Launch Round Loop
                ├── ncclLaunchKernelBefore_NoUncapturedCuda() [实测统计]
                ├── ncclLaunchKernel() [实测统计]
                ├── ncclLaunchKernelAfter_NoCuda() [实测统计]
                └── ncclLaunchFinish() [实测统计]
~~~

Rank 0 和 Rank 1 分开输出。每个 Rank 的 Send 和 Recv 都应有独立 API 与 enqueue/task append 统计。两个 Rank 的 Host 调用链可以并发推进。

## 4. 新增插桩函数

除了已有 API、Group、Prepare 和 Launch 计时，本次 Patch 还增加：

| 函数 | 用途 | 主要适用路径 |
|---|---|---|
| taskAppend | 将 API 信息转为 NCCL task | AllReduce / SendRecv |
| collTaskAppend | Collective task 入队 | AllReduce |
| p2pTaskAppend | P2P Send/Recv task 入队 | SendRecv |
| scheduleCollTasksToPlan | Collective task 规划进 Kernel Plan | AllReduce |
| scheduleP2pTasksToPlan | P2P task 配对、拆分并规划进 Kernel Plan | SendRecv |
| ncclTasksRegAndEnqueue | Collective/P2P Work 注册和入队 | 两者 |
| doLaunches | Launch 准备、round 调度和收尾 | 两者 |
| ncclPrepareTasksAndCollPreconnect | 准备任务及连接 | 两者 |
| ncclPrepareTasksAndCollPreconnectFunc | 条件异步任务准备回调 | 条件路径 |
| ncclP2PPreconnectFunc | P2P 连接预热回调 | 条件路径 |

这些函数必须在 Patch 中真实插桩，且在目标机编译后确认 CSV 中出现相应事件。未实际执行的条件路径不能被标成 0 us。

## 5. 父子关系与 Group 逻辑关系

区分：
1. **C++ 函数调用父子关系**：父函数的调用栈内直接调用子函数。
2. **Group 逻辑包含关系**：多个 API 被同一个 Group 收集，但彼此不是函数调用父子关系。
3. **异步任务提交关系**：一个函数提交 AsyncJob，稍后由其他 Host Thread 执行回调；按异步边表示，不能画成同步嵌套调用。

ncclGroupStartInternal 是 inline helper。当前 Patch 不单独计量它时，应把它说明为包含在调用方 ncclEnqueueCheck / ncclGroupStart 的时间内，而不是虚构一个独立值。

## 6. 串行与并行

~~~text
时间 ---------------------------------------------------------->

Rank 0 Host Main:
API -> Enqueue -> Task Append -> Group End -> Prepare -> Launch
                                                   |
Rank 0 Async Host (if used):                       +-> async prepare/preconnect

Rank 1 Host Main:
API -> Enqueue -> Task Append -> Group End -> Prepare -> Launch
                                                   |
Rank 1 Async Host (if used):                       +-> async prepare/preconnect

GPU 0 Stream:
                                      Kernel round 0 -> Kernel round 1 -> complete

GPU 1 Stream:
                                      Kernel round 0 -> Kernel round 1 -> complete
~~~

这是结构示意。最终时间线必须根据实际 start/end 时间戳生成，不能照抄示意顺序或假设 Rank 同时开始。

- 同一 Host Thread 中按实际调用顺序串行。
- 两个 MPI Rank 的 Host Thread 可并行。
- 异步回调可能运行在不同 TID。
- CUDA Kernel Launch 是异步提交，Host 函数返回不代表 GPU 完成。
- GPU 0 / GPU 1 的 Kernel 可并行，也可能因 NCCL peer synchronization 出现等待。
- Proxy 如实际存在，单独作为 Host Thread lane；本轮不单独统计 Proxy 时标记为未测量，不并入 Kernel。

## 7. 统计和关联要求

Host Trace 当前字段为 event、rank、pid、tid、bytes、start_ns、end_ns、duration_ns。使用 PID/TID、时间区间、API 调用顺序及源码控制流识别操作窗口。

每个函数按 Rank/TID 分组，先剔除 20 次 warmup，再统计正式 100 次。函数可能每轮调用多次，报告实际 calls，不强行要求每个函数 calls=100。

父子区间从同一线程内的区间包含关系与源码调用关系重建。Exclusive 必须扣除子区间并集，不能扣除子区间 duration 的简单总和。若缺少 event id / parent id 导致无法可靠归属，应标记 N/A。

GPU Kernel Activity 记录名称、Rank/GPU、Stream、Start、End、Duration、Grid/Block（工具可提供时）。不同 GPU 的设备绝对时钟未经校准不可直接比较；比较每个 GPU 本地 duration 和通过 CUPTI/Nsight 对齐的时间线。

## 8. 最终报告验收

最终 stage_analysis.md 必须直接包含两棵带真实耗时的层级文本树。每个函数名后都要有 calls、mean inclusive、mean exclusive、P50、P90、P99、min、max。未执行的节点写 N/A 并说明原因。

timeline.md 必须包含 Rank 0 / Rank 1 Host、异步 Host Thread（如果存在）、GPU 0 / GPU 1 Stream 的时间线，明确串行、并行、重叠和最终完成关键路径。

所有数字必须能追溯到原始 Host Trace CSV、CUPTI/Nsight 数据和 Baseline 结果。没有实际采集的数值不允许填写。
