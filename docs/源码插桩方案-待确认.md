# NCCL v2.28.9-1 阶段插桩方案（已按用户确认实施）

> 用户已确认：只修改 Host 计时逻辑；GPU Device 内部不插桩，只统计 Kernel 完整执行时间；本次阶段测试默认不启用 P2P CUDA memcpy/CE，Proxy 不做计时。正式 Host Patch 已生成，见 patches/nccl-v2.28.9-1-host-trace.patch。

## 1. 两套构建严格隔离

### Baseline（端到端）
- NVIDIA/nccl tag `v2.28.9-1` 原始源码。
- 不应用本项目 Patch，不包含 Host trace 计时逻辑。
- AllReduce / SendRecv 测 8 B、16 KiB、8 MiB，warmup 20、measure 100。
- 测试程序在 API 外测 Host API 驻留时间，并通过 stream synchronize 测 E2E；这不是 NCCL 源码插桩。

### Trace（阶段拆解）
- 同一个上游 Tag，独立源码目录和 build 输出。
- 应用 Host-only Patch，以 `NCCL_ENABLE_HOST_TRACE=1` 编译。
- 运行时设置 `NCCL_HOST_TRACE=1`、`NCCL_HOST_TRACE_BYTES=8`。
- 只运行 8 B 的 AllReduce / SendRecv，SIMPLE 和 LL 分开。
- Trace 版 E2E 只用于量化插桩扰动；正式端到端结果来自 Baseline。

## 2. Host 源码插桩点

| 文件 | 函数 | 计时目的 |
|---|---|---|
| src/collectives.cc | ncclAllReduce | AllReduce API 入口 |
| src/collectives.cc | ncclSend | Send API 入口 |
| src/collectives.cc | ncclRecv | Recv API 入口 |
| src/enqueue.cc | ncclEnqueueCheck | 参数检查、入队及触发内部 Group 处理的 Host 时间 |
| src/group.cc | ncclGroupEndInternal | Group 收尾 Host 时间 |
| src/group.cc | groupLaunch | Group launch / async job 阶段 |
| src/enqueue.cc | ncclPrepareTasks | task 整理和算法/协议选择相关 Host 阶段 |
| src/enqueue.cc | ncclLaunchPrepare | Kernel Plan / work 准备 |
| src/enqueue.cc | ncclLaunchKernelBefore_NoUncapturedCuda | uploadWork |
| src/enqueue.cc | ncclLaunchKernel | CUDA Driver Kernel launch 的 Host 驻留时间 |
| src/enqueue.cc | ncclLaunchKernelAfter_NoCuda | launch 后 host task 提交 |
| src/enqueue.cc | ncclLaunchFinish | plan/group 收尾 |

函数耗时为 inclusive wall duration。父子区间重叠，不得直接求和。Group 事件 rank=-1，因为 group 作用域不一定对应单一 communicator。

## 3. GPU Kernel 完整执行时间

不修改 Device 源码，不使用 clock64()。由测试侧 CUPTI Activity API 或 Nsight Systems 记录每个 Kernel 的 GPU start/end/duration、名称、stream、grid/block。若一个 NCCL 操作产生多个 Kernel，逐个报告并说明重叠关系，不把多个 Kernel 时间简单相加。

## 4. Proxy

NCCL v2.28.9-1 的 P2P transport 默认 `P2P_USE_CUDA_MEMCPY=0`。阶段测试脚本显式设置 `NCCL_P2P_USE_CUDA_MEMCPY=0`，目标是 direct P2P，不增加 Proxy 计时。但仍必须从 NCCL INFO 日志确认实际 transport；若切换 NET/SHM 或有其他 Proxy 工作，应在结果中如实说明。
