# NCCL v2.28.9-1 阶段插桩方案（待用户确认）

> 状态：仅完成源码调用链核对和插桩设计；尚未修改任何 NCCL 计时源码，尚未生成插桩 Patch。必须得到用户确认后才实施。

## 1. 两套构建严格隔离

### Baseline（端到端）
- 上游源码：NVIDIA/nccl tag `v2.28.9-1`。
- 不添加任何本项目的 Host/Device 时间戳、trace buffer、atomic、NVTX 或计时回调。
- 用于 AllReduce / SendRecv，8 B、16 KiB、8 MiB，warmup 20、measure 100。
- 只由测试程序在 API 外测 Host API 驻留时间，并通过 stream synchronize 测 E2E；这不是 NCCL 源码插桩。

### Trace（阶段拆解）
- 同一个上游 Tag，独立构建目录和安装目录。
- 仅对 8 B 阶段测试开启编译宏，例如 `NCCL_ENABLE_STAGE_TRACE=1`。
- 宏关闭时编译结果不包含 trace 代码；Baseline 不包含任何 trace 代码。
- 插桩事件写入预分配的固定容量缓冲区，测试结束后再导出；不在通信热路径 printf。
- trace 测试仍需报告插桩版 E2E 作为扰动对照，但它不能替代未插桩 Baseline E2E。

## 4. 拟议的 Device 阶段事件

### SIMPLE
- D0：进入实际 AllReduce/P2P work handler。
- D1：peer/step wait 开始与结束（waitPeer）。
- D2：数据读取/复制/规约阶段（reduceCopy；AllReduce 有 Reduce，SendRecv 无 Reduce）。
- D3：barrier 与 peer step/tail/head 发布阶段（postPeer 及其相邻同步）。
- D4：离开本次 primitive/work handler。

### LL
- D0：进入实际 AllReduce/P2P work handler。
- D1：send slot/step 可用性等待（waitSend）。
- D2：接收 flag/data wait（readLL/readLLBegin/Finish）。
- D3：本地数据 load、reduce、storeLL 或输出写回。
- D4：发送/接收 step 更新和完成发布。
- D5：离开本次 primitive/work handler。

阶段边界要按实际模板分支确定，不能把 SIMPLE 的 waitPeer 逻辑套给 LL。8 Byte 时还要记录每个阶段是否真的执行；未执行标记 N/A。

## 5. Device 时间戳方案需要用户确认

Device 阶段由多个 Warp/线程协作，不能简单只用 thread 0 的 clock64() 代表整个 CTA 的阶段耗时。拟提供两种方式：

**方案 A（推荐，较低扰动）**
- 每个 CTA 由指定代表线程记录阶段时间戳。
- 记录该线程所观察到的阶段耗时，明确标注为 representative-thread latency。
- 不声称是 CTA 最慢线程或完整 CTA critical path。
- 不添加全局 atomic；每个 CTA 只写少量预分配记录。

**方案 B（更接近 CTA 阶段关键路径，但扰动更大）**
- 参与阶段的线程各自记录局部 duration。
- 在阶段结束处进行 CTA 内归并，得到 max duration。
- 需要 shared memory/同步或原子操作，可能改变原有调度与同步成本。
- 必须在结果中报告插桩开销。

Host 时间戳拟用 CLOCK_MONOTONIC_RAW。Device 使用 clock64() 只计算同一 GPU 内的 duration；不比较两个 GPU 的绝对 clock64 值。

## 6. Proxy 事件的处理

只有在 plan->hasProxyOps / connector proxyProgress 实际启用时，才记录 Proxy：
- Proxy op 创建/保存。
- Proxy progress thread 中 progressOps 的每轮推进。
- op 完成/移除。

不能把 Proxy 线程空转时间计入通信阶段，也不能将 Proxy wall time 与 GPU kernel duration 简单相加。若该 PCIe P2P 路径没有 Proxy op，报告 N/A。

## 7. 插桩代码设计约束

- 独立宏控制，默认关闭；Baseline 构建完全不包含插桩代码。
- 仅在阶段测试且 payload=8 Byte 时使能。
- 使用预分配固定容量 trace buffer；记录溢出计数。
- Host 事件至少包含 rank、thread id、group/op sequence、event id、parent id、start/end ns。
- Device 事件至少包含 rank、channel/CTA、work id、stage id、start/end cycle。
- 不在热路径打印；不在热路径动态分配；尽可能不引入锁。
- 不修改 NCCL 算法、传输、同步或协议选择逻辑。
- 端到端测试链接未插桩 NCCL；阶段测试链接插桩 NCCL。
- 插桩版 E2E 只作为扰动对照，正式 E2E 结果来自 Baseline。

## 8. 请用户确认

实施前需要确认以下三项：

1. Host 事件范围：是否采用第 2 节列出的 API、enqueue/group、prepare、upload、kernel launch、after/finish 全链路；Proxy 只在实际出现时记录？
2. Device 方案：选择第 5 节的方案 A（代表线程、低扰动）还是方案 B（CTA max、更高扰动）？
3. Device 阶段：是否采用第 4 节列出的 SIMPLE/LL 阶段划分，并分别覆盖 AllReduce 和 SendRecv？
