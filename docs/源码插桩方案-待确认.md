# NCCL v2.28.9-1 阶段插桩方案（待用户确认）

> 状态：仅完成源码调用链核对和插桩设计；尚未修改任何 NCCL 计时源码，尚未生成插桩 Patch。必须得到用户确认后才实施。

## 1. 两套构建严格隔离

### Baseline（端到端）
- 上游源码：NVIDIA/nccl tag `v2.28.9-1`。
- 不添加任何本项目的 Host/Device 时间戳、trace buffer、atomic、NVTX 或计时回调。
- 用于 AllReduce / SendRecv，8 B、16 KiB、8 MiB，warmup 20、measure 100。
- 只由测试程序在 API 外测 Host API 驻留时间，并通过 stream synchronize 测 E2E；这不是 NCCL 源码插桩。

### Trace（阶段拆解）
- 同一个上游 Tag，独立构建目录和安装目录。
- 仅对 8 B 阶段测试开启编译宏，例如 `NCCL_ENABLE_STAGE_TRACE=1`。
- 宏关闭时编译结果不包含 trace 代码；Baseline 不包含任何 trace 代码。
- 插桩事件写入预分配的固定容量缓冲区，测试结束后再导出；不在通信热路径 printf。
- trace 测试仍需报告插桩版 E2E 作为扰动对照，但它不能替代未插桩 Baseline E2E。

## 4. GPU Kernel 完整执行时间（不修改 Device 源码）

用户明确要求：不在 GPU Device 代码中插入任何计时探针，不使用 clock64()，不在 waitPeer/readLL/reduceCopy/storeLL/postPeer 等 Device 阶段内部插桩。

只统计实际 CUDA Kernel 的完整执行时间：
- 使用外部 Kernel Activity 采集（优先 CUPTI Activity API；也可用 Nsight Systems 导出的 CUDA Kernel 时间线）。
- 采集每个 kernel 的 GPU start/end 时间戳和 duration，并关联 kernel 名称、grid/block、stream、rank、测试轮次。
- 不修改 NCCL Device 源码，不增加 Device trace buffer，不增加 CTA 内同步或 atomic。
- 若一个 NCCL collective launch 产生多个 kernel，逐个报告 kernel duration；不能把多个 kernel 的时间误称为单个 kernel。
- 若需要统计某一次 NCCL 操作对应的总 GPU kernel 时间，可按该次操作关联到的 kernel 列表分别报告，并说明是否存在重叠；不能直接将有重叠的 kernel duration 求和。
- CUDA Event 仅适合明确知道操作边界且 stream 上 kernel 关系可控的场景；若目标是区分每个 kernel 的完整执行时间，优先使用 CUPTI/Nsight Systems 的 kernel activity 记录。

说明：这是测试侧外部采集，不是 NCCL Device 插桩。若要求连外部 profiler/activity tracing 也不启用，则无法得到逐个 kernel 的精确执行时间，只能用 CUDA Event 测量 stream 上一段操作的耗时。

## 5. Proxy 是否需要计时

本次目标路径为同机 PCIe P2P。NCCL v2.28.9-1 的 `src/transport/p2p.cc` 已核实：
- `NCCL_PARAM(P2pUseCudaMemcpy, "P2P_USE_CUDA_MEMCPY", 0)`，默认关闭 CE/memcpy 路径。
- 默认 `useMemcpy == 0` 时，P2P 连接使用远端 GPU 可访问的连接内存指针（如 tail/head/ptrExchange），不启用 P2P 的 `proxyProgress` 回调。
- 只有 `NCCL_P2P_USE_CUDA_MEMCPY=1` 时，P2P transport 才设置 `p2pSendProxyConnect` 和 `p2pSendProxyProgress`，进入 CE/memcpy 相关 Proxy 路径。

因此，若测试确认使用默认直接 P2P（`NCCL_P2P_USE_CUDA_MEMCPY=0`，且没有切换到 NET/SHM 等需要 Proxy 的 transport），本轮不对 Proxy 线程插桩，也不统计 Proxy 阶段。测试日志应确认实际 Transport 为 P2P，且 CE/memcpy 未启用。

## 7. 插桩代码设计约束

- 独立宏控制，默认关闭；Baseline 构建完全不包含插桩代码。
- 仅在阶段测试且 payload=8 Byte 时使能。
- 使用预分配固定容量 trace buffer；记录溢出计数。
- Host 事件至少包含 rank、thread id、group/op sequence、event id、parent id、start/end ns。
- GPU Kernel Activity 事件至少包含 rank、kernel 名称、stream、grid/block、测试轮次、GPU start/end 和 duration；由测试侧关联 NCCL operation。
- 不在热路径打印；不在热路径动态分配；尽可能不引入锁。
- 不修改 NCCL 算法、传输、同步或协议选择逻辑。
- 端到端测试链接未插桩 NCCL；阶段测试链接插桩 NCCL。
- 插桩版 E2E 只作为扰动对照，正式 E2E 结果来自 Baseline。
