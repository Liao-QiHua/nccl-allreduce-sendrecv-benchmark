# AllReduce / SendRecv 阶段耗时层级文本图报告模板

> 本文件是最终阶段分析报告的强制格式模板。最终报告必须把实际测量值直接写在每个函数名称后面，不能只提供独立统计表。所有示例中的统计值均为占位符，正式报告必须替换为真实数据。

## 1. 每个函数节点的统一格式

```text
functionName() [calls=N, mean inclusive=X us, mean exclusive=Y us,
                P50=..., P90=..., P99=..., min=..., max=...]
```

- `calls`：正式 100 次测量窗口中实际调用次数。某函数每轮被调用多次时，报告真实次数。
- `mean inclusive`：该函数完整 wall-time 区间的均值。
- `mean exclusive`：扣除直接子函数区间并集后的自身时间。
- P50/P90/P99/min/max：基于正式测量窗口内的逐次样本。
- 所有时间统一使用 us。
- 20 次 warmup 必须排除。
- 未执行的条件分支标记 `N/A (not executed)`，不得写 0 us。
- 如果 Exclusive 无法可靠重建，标记 `N/A (insufficient event attribution)`，不得猜测。

## 2. AllReduce 调用树

按实际源码控制流核实直接父子关系后填充：

```text
Rank 0 Host Thread
└── ncclAllReduce() [实测统计]
    └── ncclEnqueueCheck() [实测统计]
        ├── ncclGroupStartInternal() [inline；通常不单独计时]
        ├── taskAppend() [实测统计]
        │   └── collTaskAppend() [实测统计]
        └── ncclGroupEndInternal() [实测统计]
            └── groupLaunch() [实测统计]
                ├── ncclP2PPreconnectFunc() [条件执行；否则 N/A]
                ├── ncclPrepareTasksAndCollPreconnect() [实测统计]
                │   ├── ncclPrepareTasks() [实测统计]
                │   └── ncclPrepareTasksAndCollPreconnectFunc() [异步条件路径；否则 N/A]
                ├── ncclTasksRegAndEnqueue() [实测统计]
                └── doLaunches() [实测统计]
                    ├── ncclLaunchPrepare() [实测统计]
                    │   └── scheduleCollTasksToPlan() [实测统计]
                    └── Launch Round Loop
                        ├── ncclLaunchKernelBefore_NoUncapturedCuda() [实测统计]
                        ├── ncclLaunchKernel() [实测统计]
                        ├── ncclLaunchKernelAfter_NoCuda() [实测统计]
                        └── ncclLaunchFinish() [实测统计]
```

Rank 1 必须单独生成同样结构的统计树。若两个 Rank 的执行路径不同，应按实际路径分别展示，不能复制 Rank 0 的数值。

## 3. Send/Recv 调用树

Group 是逻辑作用域。GroupStart/GroupEnd 不是 Send/Recv API 的 C++ 函数调用父节点。应分别展示 API 调用链和 Group 提交/launch 链：

```text
Rank 0 Host Thread

ncclGroupStart() [实测统计；Group 作用域开始]

ncclSend() [实测统计]
└── ncclEnqueueCheck() [实测统计]
    └── taskAppend() [实测统计]
        └── p2pTaskAppend() [实测统计]

ncclRecv() [实测统计]
└── ncclEnqueueCheck() [实测统计]
    └── taskAppend() [实测统计]
        └── p2pTaskAppend() [实测统计]

ncclGroupEnd() [实测统计；Group 作用域结束]
└── ncclGroupEndInternal() [实测统计]
    └── groupLaunch() [实测统计]
        ├── ncclP2PPreconnectFunc() [条件执行；否则 N/A]
        ├── ncclPrepareTasksAndCollPreconnect() [实测统计]
        │   ├── ncclPrepareTasks() [实测统计]
        │   └── ncclPrepareTasksAndCollPreconnectFunc() [异步条件路径；否则 N/A]
        ├── ncclTasksRegAndEnqueue() [实测统计]
        └── doLaunches() [实测统计]
            ├── ncclLaunchPrepare() [实测统计]
            │   └── scheduleP2pTasksToPlan() [实测统计]
            └── Launch Round Loop
                ├── ncclLaunchKernelBefore_NoUncapturedCuda() [实测统计]
                ├── ncclLaunchKernel() [实测统计]
                ├── ncclLaunchKernelAfter_NoCuda() [实测统计]
                └── ncclLaunchFinish() [实测统计]
```

Rank 1 也必须单独输出。Rank 0 / Rank 1 的 Send、Recv API 与 task append 时间分别统计。

## 4. GPU Kernel 节点

GPU Kernel 不是 Host C++ 函数调用树的子函数。应在调用树后另设 GPU 执行树/泳道，关联到对应 Rank 和 CUDA Stream：

```text
Rank 0 / GPU 0 / CUDA Stream S
└── NCCL Kernel name [count=N, mean duration=X us, P50=..., P99=...]

Rank 1 / GPU 1 / CUDA Stream S
└── NCCL Kernel name [count=N, mean duration=X us, P50=..., P99=...]
```

必须按 CUPTI/Nsight 实际结果报告 Kernel 数量和名称。一次操作可能对应多个 Kernel；重叠 Kernel 不得直接相加。

## 5. 串行 / 并行时间线

最终报告必须输出由实际时间戳生成的时间线，至少包含：

- Rank 0 Host Main Thread
- Rank 1 Host Main Thread
- 异步 Host Thread（如果实际存在）
- GPU 0 Stream
- GPU 1 Stream

示意格式（最终必须替换为真实相对时间和事件）：

```text
时间 ------------------------------------------------------------>

Rank 0 Host : API -> Enqueue -> GroupEnd -> Prepare -> Launch
Rank 1 Host :   API -> Enqueue -> GroupEnd -> Prepare -> Launch
Rank 0 Async:                 async preconnect/prepare (if any)
Rank 1 Async:                   async preconnect/prepare (if any)
GPU 0 Stream:                                Kernel 0 -> Kernel 1
GPU 1 Stream:                                  Kernel 0 -> Kernel 1
```

明确标出：
1. 同一 Host Thread 内串行调用。
2. 两个 Rank 的并行推进。
3. 不同 TID 的异步任务。
4. Host Kernel Launch 与 GPU Kernel 执行的重叠。
5. GPU 0 / GPU 1 Kernel 的重叠或等待。
6. 本轮通信的最终完成时刻和关键路径。

不能把示意图当成实测图；最终时间线必须依据原始时间戳。

## 6. 时间统计正确性

- Parent / child 的 Inclusive 区间通常嵌套，禁止直接求和。
- Exclusive 应扣除同一线程中直接子区间的时间并集，而不是所有子函数 duration 的简单总和。
- 异步回调运行在不同 TID 时，显示异步提交/执行边，不得画成同步调用栈子节点。
- Group API 是逻辑作用域边界，不等于函数调用父子关系。
- 没有实际执行的条件函数标记 N/A。
- 原始事件无法可靠关联到具体操作时，明确说明限制，不得强行分配。
- 所有汇总值必须能回溯到 raw CSV / CUPTI / Nsight 原始记录。

## 7. 最终报告最低验收条件

- AllReduce：Rank 0、Rank 1 各有一棵带实测耗时的层级树。
- Send/Recv：Rank 0、Rank 1 各有一棵带实测耗时的层级树。
- 每个实际执行的函数节点后都有 calls、mean inclusive、mean exclusive、P50、P90、P99、min、max。
- 每个未执行条件分支明确标记 N/A 和原因。
- GPU Kernel 单独列出完整执行时间。
- 有基于实测时间戳的 Host/GPU 串并行时间线。
- 端到端结果与阶段插桩结果分开报告；正式 E2E 必须来自未插桩 Baseline。
